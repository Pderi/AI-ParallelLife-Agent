# 跨域问题修复说明

## 🐛 问题描述

前端请求无法发送，浏览器控制台显示请求被阻止，可能是跨域（CORS）问题。

## 🔍 问题原因

1. **前端流式请求使用了绝对URL**：`http://localhost:8123/api`，绕过了Vite代理
2. **后端缺少CORS配置**：Spring Boot应用没有配置跨域支持

## ✅ 修复方案

### 1. 前端修复

**修改文件**：`frontend/src/api/parallelLife.ts` 和 `frontend/src/api/client.ts`

**修改内容**：
- 将绝对URL `http://localhost:8123/api` 改为相对路径 `/api`
- 在开发环境，相对路径会通过Vite代理转发到后端
- 在生产环境，可以通过环境变量 `VITE_API_BASE_URL` 配置

**修改前**：
```typescript
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8123/api'
```

**修改后**：
```typescript
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || '/api'
```

### 2. 后端修复

**新增文件**：`src/main/java/com/qin/qaiagentproject/config/CorsConfig.java`

**配置内容**：
- 使用 `WebMvcConfigurer` 配置CORS映射
- 使用 `CorsFilter` 作为过滤器
- 允许所有来源、所有方法、所有请求头
- 支持携带凭证
- 设置预检请求缓存时间

### 3. Vite代理优化

**修改文件**：`frontend/vite.config.ts`

**优化内容**：
- 添加代理日志（便于调试）
- 确保代理正确转发请求

## 🚀 使用说明

### 开发环境

1. **前端**：使用相对路径 `/api`，Vite会自动代理到 `http://localhost:8123`
2. **后端**：CORS配置允许所有来源（开发环境）

### 生产环境

1. **前端**：通过环境变量 `VITE_API_BASE_URL` 配置后端地址
2. **后端**：建议修改CORS配置，只允许特定域名访问

## 📝 环境变量配置

### 开发环境（使用Vite代理）

`.env` 文件可以留空或使用：
```env
VITE_API_BASE_URL=/api
```

### 生产环境

`.env.production` 文件：
```env
VITE_API_BASE_URL=https://api.example.com/api
```

## 🔧 验证修复

1. **重启后端服务**：确保CORS配置生效
2. **重启前端开发服务器**：确保代理配置生效
3. **检查网络请求**：
   - 打开浏览器开发者工具
   - 查看Network标签
   - 确认请求状态为200或正常响应
   - 检查响应头是否包含CORS相关头

## 🐛 如果仍有问题

1. **检查后端是否运行**：确认 `http://localhost:8123` 可访问
2. **检查Vite代理**：查看控制台是否有代理日志
3. **检查浏览器控制台**：查看具体错误信息
4. **检查网络请求**：查看请求URL和响应状态
