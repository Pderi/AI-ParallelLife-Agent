# Q-AI-Agent-Project 业务流程文档

## 1. 项目概述

本项目是一个基于 Spring AI 和阿里云百炼大模型的 AI 代理系统，主要包含两个核心应用：

1. **ParallelLifeApp（平行宇宙人生模拟器）**：通过AI模拟不同人生路径，帮助用户探索人生可能性、理解决策影响、获得人生规划建议
2. **qManus（通用AI代理）**：可自主规划执行任务的智能代理

项目采用 Spring Boot 3.4.8 框架，集成 Spring AI Alibaba，支持多种对话模式、工具调用、RAG 增强等功能。

## 2. 技术架构

### 2.1 核心技术栈

- **框架**：Spring Boot 3.4.8
- **AI框架**：Spring AI Alibaba 1.0.0-M6.1
- **大模型**：阿里云百炼（通义千问 qwen-plus）
- **向量存储**：SimpleVectorStore（内存向量存储）
- **序列化**：Kryo 5.6.2（用于对话记忆持久化）
- **文档处理**：MarkdownDocumentReader
- **PDF生成**：iText 9.1.0

## 3. 核心业务流程

### 3.1 ParallelLifeApp 业务流程

ParallelLifeApp 是项目的核心业务应用，提供平行宇宙人生模拟服务。通过AI模拟不同人生路径，帮助用户探索人生可能性、理解决策影响、获得人生规划建议。支持四种对话模式：

#### 3.1.1 基础对话模式（doChat）

**流程说明**：
1. 用户发送消息和会话ID（chatId）
2. 系统从文件加载该会话的历史对话记录（最多10条）
3. 将用户消息和历史记录一起发送给大模型
4. 大模型基于系统提示词和上下文生成回复
5. 保存新的对话记录到文件
6. 返回AI回复给用户

**系统提示词**：
```
你是一位资深的人生规划师和未来学家，擅长通过多维度分析模拟不同人生路径。

你的核心能力：
1. 基于用户当前情况，模拟多个平行宇宙的人生发展
2. 分析不同决策的影响和后果
3. 评估各种人生路径的成功概率和风险
4. 提供基于数据的人生规划建议

模拟原则：
- 基于真实数据和行业趋势，而非纯幻想
- 考虑个人能力、性格、资源等实际情况
- 提供3-5个不同的平行宇宙路径
- 每个宇宙包含详细的时间线、关键事件、人生指标
- 评估实现概率（基于客观因素）

分析维度：
- 职业发展：职位、薪资、工作内容、行业地位
- 个人成长：技能、知识、经验、影响力
- 财务状况：收入、资产、财务自由度
- 生活方式：居住地、工作方式、生活节奏
- 人际关系：社交圈、重要关系、网络资源
- 幸福感：工作满意度、生活满意度、成就感

开场语：
"欢迎来到平行宇宙人生模拟器！我是你的专属人生规划师。
告诉我你当前的情况或想要探索的人生选择，我将为你模拟多个平行宇宙，
帮你预览不同路径的可能结果。"
```

**关键组件**：
- `FileBasedChatMemory`：基于文件的对话记忆，使用Kryo序列化
- `MessageChatMemoryAdvisor`：自动管理对话上下文
- `MyLoggerAdvisor`：记录请求和响应日志
- `ForbiddenWordAdvisor`：违禁词过滤（暴力、色情、诈骗、毒品、赌博）

**数据流向**：
```
用户消息 → ChatClient → MessageChatMemoryAdvisor (加载历史) 
→ ForbiddenWordAdvisor (过滤) → MyLoggerAdvisor (日志) 
→ 大模型API → 响应处理 → 保存对话记录 → 返回结果
```

#### 3.1.2 带报告模式（doChatWithReport）

**流程说明**：
1. 执行基础对话流程
2. 要求大模型生成结构化的平行人生报告
3. 返回 `ParallelLifeReport` 对象，包含多个平行宇宙的详细分析

**数据结构**：
```java
record ParallelLifeReport(
    String title,
    String currentSituation,
    List<Universe> universes,
    String comparison,
    List<String> recommendations
)
```

**特点**：
- 使用结构化输出（entity方法）
- 每次对话后自动生成报告
- 包含3-5个平行宇宙的详细分析
- 每个宇宙包含时间线、关键事件、人生指标、实现概率
- 提供对比分析和建议

#### 3.1.3 RAG增强模式（doChatWithRag）

**流程说明**：
1. 用户发送消息
2. 系统从向量存储中检索相关文档（基于语义相似度）
3. 将检索到的文档作为上下文注入提示词
4. 大模型基于知识库和用户问题生成回答
5. 返回增强后的回复

**知识库构建流程**：
1. 启动时加载 `resources/document/` 目录下的Markdown文件
2. 使用 `MarkdownDocumentReader` 解析文档
3. 提取文档元数据（文件名、状态标签）
4. 使用 `EmbeddingModel` 生成向量
5. 存储到 `SimpleVectorStore`

**知识库文档**：
- `职业发展路径-技术类.md`：程序员职业发展路径、成功概率评估
- `决策分析方法论.md`：决策分析框架、风险评估方法
- `人生规划方法论.md`：人生规划步骤、工具和建议

**关键组件**：
- `ParallelLifeDocumentLoader`：文档加载器
- `ParallelLifeVectorStoreConfig`：向量存储配置
- `QuestionAnswerAdvisor`：RAG增强顾问

**数据流向**：
```
用户消息 → QuestionAnswerAdvisor (向量检索) 
→ 检索相关文档 → 注入上下文 → 大模型API 
→ 生成回答 → 返回结果
```

#### 3.1.4 工具调用模式（doChatWithTools）

**流程说明**：
1. 用户发送消息
2. 大模型分析需求，决定是否需要调用工具
3. 如果需要，选择并调用合适的工具
4. 将工具执行结果返回给大模型
5. 大模型基于工具结果生成最终回复
6. 返回给用户

**可用工具**：
- `FileOperationTool`：文件读写操作
- `WebSearchTool`：百度搜索
- `WebScrapingTool`：网页内容抓取
- `ResourceDownloadTool`：资源下载
- `TerminalOperationTool`：终端命令执行
- `PDFGenerationTool`：PDF文件生成
- `TerminateTool`：任务终止

**工具调用流程**：
```
用户消息 → 大模型分析 → 选择工具 → 执行工具 
→ 工具结果 → 大模型处理 → 生成回复 → 返回用户
```

### 3.2 qManus 通用代理业务流程

qManus 是一个可自主规划执行任务的通用AI代理，基于 ReAct（Reasoning and Acting）模式。

#### 3.2.1 代理架构

**继承关系**：
```
BaseAgent (抽象基类)
  └── ReActAgent (ReAct模式抽象类)
      └── ToolCallAgent (工具调用实现)
          └── qManus (具体代理)
```

#### 3.2.2 执行流程

**状态机**：
```
IDLE → RUNNING → FINISHED/ERROR
```

**执行步骤**：
1. **初始化**：设置系统提示词、下一步提示词、最大步数（20步）
2. **运行循环**：
   - 执行 `think()` 方法：分析当前状态，决定下一步行动
   - 如果需要行动，执行 `act()` 方法：调用工具并处理结果
   - 检查是否调用了终止工具，如果是则结束
   - 重复直到达到最大步数或任务完成
3. **清理资源**：执行 `cleanup()` 方法

**think() 方法流程**：
```
构建提示词 → 调用大模型（带工具选项） 
→ 解析响应 → 检查工具调用 
→ 返回是否需要执行行动
```

**act() 方法流程**：
```
执行工具调用 → 获取工具结果 
→ 更新对话上下文 → 检查终止工具 
→ 更新状态 → 返回结果
```

**系统提示词**：
```
You are qManus, an all-capable AI assistant, aimed at solving any task presented by the user.
You have various tools at your disposal that you can call upon to efficiently complete complex requests.
```

**下一步提示词**：
```
Based on user needs, proactively select the most appropriate tool or combination of tools.
For complex tasks, you can break down the problem and use different tools step by step to solve it.
After using each tool, clearly explain the execution results and suggest the next steps.
If you want to stop the interaction at any point, use the `terminate` tool/function call.
```

## 4. 核心组件详解

### 4.1 Advisor 系统

Advisor 是 Spring AI 的拦截器机制，可以在对话前后执行自定义逻辑。

#### 4.1.1 MyLoggerAdvisor

**功能**：记录请求和响应的日志

**实现**：
- 实现 `CallAroundAdvisor` 和 `StreamAroundAdvisor`
- 在请求前记录用户消息
- 在响应后记录AI回复

**优先级**：0（默认）

#### 4.1.2 ForbiddenWordAdvisor

**功能**：违禁词过滤

**违禁词列表**：
- 暴力
- 色情
- 诈骗
- 毒品
- 赌博

**实现**：
- 使用正则表达式匹配违禁词
- 在用户输入和AI输出时都进行检查
- 发现违禁词时抛出 `SecurityException`

**优先级**：100（高优先级，优先执行）

#### 4.1.3 ReReadingAdvisor

**功能**：推理增强（Re2模式）

**实现**：
- 将用户问题重复两次，提高模型理解能力
- 注意：开启后成本翻倍

**优先级**：0（默认）

### 4.2 对话记忆系统

#### 4.2.1 FileBasedChatMemory

**功能**：基于文件的持久化对话记忆

**实现**：
- 使用 Kryo 序列化库
- 每个会话保存为独立文件：`{chatId}.kryo`
- 文件存储在：`{user.dir}/tmp/chat-memory/`

**方法**：
- `add(conversationId, messages)`：添加消息
- `get(conversationId, lastN)`：获取最近N条消息
- `clear(conversationId)`：清除会话记录

**特点**：
- 持久化存储，服务重启后仍可恢复
- 支持多会话并发
- 自动创建目录

### 4.3 工具系统

所有工具都使用 `@Tool` 注解标记，通过 `ToolRegistration` 统一注册。

#### 4.3.1 FileOperationTool

**功能**：文件读写操作

**方法**：
- `readFile(fileName)`：读取文件内容
- `writeFile(fileName, content)`：写入文件内容

**存储路径**：`{user.dir}/tmp/file/`

#### 4.3.2 WebSearchTool

**功能**：百度搜索

**实现**：
- 调用 SearchAPI 的百度搜索接口
- 返回前5条搜索结果

**配置**：需要 `search-api.api-key` 配置项

#### 4.3.3 WebScrapingTool

**功能**：网页内容抓取

**实现**：
- 使用 Jsoup 库
- 返回网页的HTML内容

#### 4.3.4 ResourceDownloadTool

**功能**：资源下载

**方法**：
- `downloadResource(url, fileName)`：下载资源到本地

**存储路径**：`{user.dir}/tmp/download/`

#### 4.3.5 TerminalOperationTool

**功能**：终端命令执行

**实现**：
- 使用 `ProcessBuilder` 执行命令
- 支持 Windows 系统（cmd.exe）
- 返回命令执行结果

**安全注意**：此工具具有较高风险，需谨慎使用

#### 4.3.6 PDFGenerationTool

**功能**：PDF文件生成

**实现**：
- 使用 iText 库
- 支持中文字体（STSongStd-Light）
- 将文本内容转换为PDF

**存储路径**：`{user.dir}/tmp/pdf/`

#### 4.3.7 TerminateTool

**功能**：任务终止

**方法**：
- `doTerminate()`：终止当前任务

**用途**：代理完成任务后调用此工具结束执行

### 4.4 RAG 系统

#### 4.4.1 文档加载

**组件**：`ParallelLifeDocumentLoader`

**流程**：
1. 扫描 `classpath:document/*.md` 文件
2. 提取文件名和类别（职业发展、决策分析、人生规划等）
3. 使用 `MarkdownDocumentReader` 解析
4. 配置元数据（文件名、类别）
5. 返回文档列表

**文档配置**：
- 水平分割线创建新文档：`true`
- 包含代码块：`false`
- 包含引用块：`false`

#### 4.4.2 向量存储

**组件**：`ParallelLifeVectorStoreConfig`

**实现**：
- 使用 `SimpleVectorStore`（内存存储）
- 使用 `EmbeddingModel` 生成向量
- 启动时加载所有文档到向量存储

**注意**：当前使用内存存储，服务重启后需重新加载

### 4.5 代理系统

#### 4.5.1 BaseAgent

**功能**：代理基类，提供状态管理和执行循环

**核心方法**：
- `run(userPrompt)`：运行代理
- `step()`：执行单步（抽象方法，子类实现）
- `cleanup()`：清理资源

**状态管理**：
- `IDLE`：空闲
- `RUNNING`：运行中
- `FINISHED`：已完成
- `ERROR`：错误

#### 4.5.2 ReActAgent

**功能**：ReAct模式抽象类

**核心方法**：
- `think()`：思考（抽象方法）
- `act()`：行动（抽象方法）
- `step()`：实现思考-行动循环

#### 4.5.3 ToolCallAgent

**功能**：工具调用代理实现

**核心方法**：
- `think()`：调用大模型，分析是否需要工具
- `act()`：执行工具调用，处理结果

**特点**：
- 禁用 Spring AI 内置工具调用机制
- 自主维护对话上下文
- 支持工具调用链

## 9. 业务流程总结

### 9.1 ParallelLifeApp 业务场景

1. **人生探索**：用户描述当前情况或想要探索的人生选择
2. **平行宇宙模拟**：系统生成3-5个不同的平行宇宙路径
3. **多维度分析**：从职业发展、财务状况、个人成长、生活方式等维度分析
4. **概率评估**：评估每个路径的成功概率和风险等级
5. **对比分析**：对比不同路径的优劣，提供建议
6. **可选增强**：
   - RAG增强：基于职业发展、决策分析、人生规划知识库提供专业建议
   - 工具调用：搜索行业数据、薪资水平、成功率等实时信息，生成PDF报告

### 9.2 qManus 业务场景

1. **任务接收**：用户描述复杂任务
2. **任务分解**：代理分析任务，分解为多个步骤
3. **工具选择**：根据需求选择合适的工具
