## 二、方案映射（简化文档 ↔ 本仓库）

| 简化方案概念 | 本仓库落地 |
| --- | --- |
| `users` + `hot_memory` + `warm_memory` + `cold_memory` + `rag_knowledge`（单 PG） | **MySQL**：用户、会话、消息、工具审计、冷记忆流水；**Redis**：热记忆（全局锚点 + 会话摘要）；**PostgreSQL**：温记忆 topic + RAG/向量扩展（见 DDL 主文档） |
| `getHotMemory` / `recallWarmMemory` / `recallRAG` | `ContextManager` + 各 Provider（Hot/Warm/RAG）并行组装 |
| `appendColdMemory` → `extractColdToWarm` | 先写 MySQL 消息/冷表 → **异步**提炼 → 写 PG Warm +（可选）更新 Redis 热索引 |
| Express `/api/chat` | 现有 `ParallelLifeController` + 编排下沉至 Service；是否新增 REST 见 Phase API |

## 六、风险登记（跟踪栏）

| 风险 | 影响 | 缓解 | 状态 |
| --- | --- | --- | --- |
| 双数据源事务边界不清 | 数据不一致 | 主事务仅 MySQL；PG/Redis 事件化 | ☐ |
| 向量维度与模型不一致 | 检索失效 | 单一 embedding 模型 + DDL 固定维度 | ☐ |
| 流式 + 长上下文构建耗时 | 首字延迟 | 超时降级、缓存 Hot | ☐ |
| 与现有 Spring AI Advisor 冲突 | 重复记忆 | 新旧开关 + 单一活跃路径 | ☐ |
