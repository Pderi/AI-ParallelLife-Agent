# 数据持久化前置设计：数据库表结构方案（PostgreSQL）

> 说明（2026-04-20）：本文件为前置方案文档，执行层面的建表与字段细节请以 `docs-back/三层记忆DDL设计文档-Redis+PostgreSQL+MySQL.md` 为准。
> 本文主要保留为历史设计边界与演进背景说明。

## 1. 目标与范围
本方案用于在正式进行“数据持久化改造”前，先完成数据库表结构设计与落地边界定义，降低后续编码与迁移风险。

本次设计覆盖：
1. 会话与消息主链路（P0 最小闭环）
2. 工具调用审计（安全与排障）
3. 可选扩展表（记忆与文档索引）

不在本次范围内：
- 向量库最终选型细节（后续在 RAG/pgvector 专项文档细化）
- 全量历史数据迁移脚本实现

---

## 2. 设计原则
1. **先最小闭环**：优先保证“创建会话 + 写消息 + 查消息”完整可用。
2. **可扩展**：表结构预留多租户、审计、软删除与扩展字段能力。
3. **高并发友好**：主查询路径有索引，避免全表扫描。
4. **可治理**：字段命名一致、状态明确、时间字段完整。

---

## 3. 命名与通用约定
1. 命名：`snake_case`。
2. 主键：`bigserial`（内部主键）+ 业务唯一键（如 `chat_id`、`message_id`）。
3. 时间：统一 `timestamptz`，保留 `created_at`、`updated_at`。
4. 软删除：`deleted_at`（默认 `null`）。
5. 租户：预留 `tenant_id`（当前可先默认值 `default`）。

---

## 4. 核心表设计（P0 必做）

## 4.1 会话表：`chat_session`
用途：管理会话元数据，支持会话创建、查询、归档。

建议字段：
- `id` `bigserial` PK
- `chat_id` `varchar(64)` UNIQUE NOT NULL（对外会话 ID）
- `tenant_id` `varchar(64)` NOT NULL DEFAULT 'default'
- `user_id` `varchar(64)` NULL
- `session_name` `varchar(128)` NULL
- `status` `varchar(20)` NOT NULL DEFAULT 'ACTIVE'（ACTIVE/CLOSED/ARCHIVED）
- `message_count` `integer` NOT NULL DEFAULT 0
- `last_message_at` `timestamptz` NULL
- `created_at` `timestamptz` NOT NULL DEFAULT now()
- `updated_at` `timestamptz` NOT NULL DEFAULT now()
- `deleted_at` `timestamptz` NULL

关键索引：
1. `uk_chat_session_chat_id(chat_id)` 唯一索引
2. `idx_chat_session_user_created(user_id, created_at desc)`
3. `idx_chat_session_status_updated(status, updated_at desc)`

---

## 4.2 消息表：`chat_message`
用途：存储对话消息与角色信息，支撑上下文恢复。

建议字段：
- `id` `bigserial` PK
- `message_id` `varchar(64)` UNIQUE NOT NULL（业务消息 ID）
- `chat_id` `varchar(64)` NOT NULL（外键指向 `chat_session.chat_id`）
- `tenant_id` `varchar(64)` NOT NULL DEFAULT 'default'
- `role` `varchar(20)` NOT NULL（SYSTEM/USER/ASSISTANT/TOOL）
- `content` `text` NOT NULL
- `content_tokens` `integer` NULL
- `seq_no` `integer` NOT NULL（会话内单调递增序号）
- `metadata_json` `jsonb` NULL（模型名、是否RAG、是否工具调用等）
- `created_at` `timestamptz` NOT NULL DEFAULT now()
- `deleted_at` `timestamptz` NULL

约束与索引：
1. 外键：`fk_chat_message_chat_id` -> `chat_session(chat_id)`
2. 唯一：`uk_chat_message_chat_seq(chat_id, seq_no)`
3. 索引：`idx_chat_message_chat_created(chat_id, created_at)`
4. 索引：`idx_chat_message_tenant_created(tenant_id, created_at desc)`

---

## 4.3 工具调用审计表：`tool_call_audit`
用途：记录工具执行轨迹，支持安全审计与问题排查。

建议字段：
- `id` `bigserial` PK
- `trace_id` `varchar(64)` NULL
- `chat_id` `varchar(64)` NULL
- `message_id` `varchar(64)` NULL
- `tool_name` `varchar(64)` NOT NULL
- `request_summary` `text` NULL（脱敏后的请求摘要）
- `result_summary` `text` NULL（脱敏后的结果摘要）
- `status` `varchar(20)` NOT NULL（SUCCESS/FAILED/BLOCKED）
- `error_code` `varchar(32)` NULL
- `error_message` `text` NULL
- `duration_ms` `integer` NULL
- `created_at` `timestamptz` NOT NULL DEFAULT now()

关键索引：
1. `idx_tool_call_audit_chat_created(chat_id, created_at desc)`
2. `idx_tool_call_audit_tool_status_created(tool_name, status, created_at desc)`

---

## 5. 扩展表设计（P1/P2 预留）

## 5.1 会话摘要表（可选）：`chat_session_summary`
用途：缓存会话压缩摘要，减少上下文构建成本。

字段建议：
- `id` `bigserial` PK
- `chat_id` `varchar(64)` UNIQUE NOT NULL
- `summary_text` `text` NOT NULL
- `summary_version` `integer` NOT NULL DEFAULT 1
- `updated_at` `timestamptz` NOT NULL DEFAULT now()

## 5.2 记忆索引表（可选）：`memory_topic_index`
用途：与 `MEMORY.md/topics` 协同，记录结构化索引和质量评分。

字段建议：
- `id` `bigserial` PK
- `topic_id` `varchar(64)` UNIQUE NOT NULL
- `title` `varchar(128)` NOT NULL
- `tags` `jsonb` NULL
- `priority` `varchar(16)` NOT NULL DEFAULT 'medium'
- `quality_score` `numeric(4,3)` NULL
- `ttl_days` `integer` NULL
- `last_verified_at` `timestamptz` NULL
- `updated_at` `timestamptz` NOT NULL DEFAULT now()

---

## 6. 初版 DDL 草案（可直接用于 Flyway V1）

```sql
create table if not exists chat_session (
  id bigserial primary key,
  chat_id varchar(64) not null unique,
  tenant_id varchar(64) not null default 'default',
  user_id varchar(64),
  session_name varchar(128),
  status varchar(20) not null default 'ACTIVE',
  message_count integer not null default 0,
  last_message_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz
);

create index if not exists idx_chat_session_user_created
  on chat_session(user_id, created_at desc);

create index if not exists idx_chat_session_status_updated
  on chat_session(status, updated_at desc);

create table if not exists chat_message (
  id bigserial primary key,
  message_id varchar(64) not null unique,
  chat_id varchar(64) not null,
  tenant_id varchar(64) not null default 'default',
  role varchar(20) not null,
  content text not null,
  content_tokens integer,
  seq_no integer not null,
  metadata_json jsonb,
  created_at timestamptz not null default now(),
  deleted_at timestamptz,
  constraint fk_chat_message_chat_id
    foreign key (chat_id) references chat_session(chat_id)
);

create unique index if not exists uk_chat_message_chat_seq
  on chat_message(chat_id, seq_no);

create index if not exists idx_chat_message_chat_created
  on chat_message(chat_id, created_at);

create index if not exists idx_chat_message_tenant_created
  on chat_message(tenant_id, created_at desc);

create table if not exists tool_call_audit (
  id bigserial primary key,
  trace_id varchar(64),
  chat_id varchar(64),
  message_id varchar(64),
  tool_name varchar(64) not null,
  request_summary text,
  result_summary text,
  status varchar(20) not null,
  error_code varchar(32),
  error_message text,
  duration_ms integer,
  created_at timestamptz not null default now()
);

create index if not exists idx_tool_call_audit_chat_created
  on tool_call_audit(chat_id, created_at desc);

create index if not exists idx_tool_call_audit_tool_status_created
  on tool_call_audit(tool_name, status, created_at desc);
```

---

## 7. 落地顺序建议（小步迭代）
1. 第一步：只上 `chat_session` + `chat_message`，打通创建会话与消息读写。
2. 第二步：接入 `tool_call_audit`，先审计高风险工具调用（terminal/file/web）。
3. 第三步：再引入摘要表/记忆索引表，服务上下文压缩与记忆治理。

---

## 8. 与现有代码映射建议
1. `ParallelLifeController.createSession()` -> `chat_session` 插入。
2. `chat/stream` 与 `chat` 主链路 -> `chat_message` 追加写入。
3. 工具执行层（`ToolRegistration` 注册工具）-> `tool_call_audit` 记录调用结果。

---

## 9. 验收标准（本阶段）
1. 能通过 SQL 建表并成功启动应用。
2. 能完成“创建会话 + 写入用户消息 + 查询最近 N 条消息”闭环。
3. 出现工具异常时，`tool_call_audit` 有记录（至少失败状态和错误摘要）。
4. 不影响现有接口兼容性（优先新增，不破坏旧路径）。
